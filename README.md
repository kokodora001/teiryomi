# あそびば（ティアよみ / 絵描き人狼）

友達とオンラインで遊べるパーティーゲーム集です。トップページ（index.html）でゲームを選びます。

- **ティアよみ**：出題者のティア表をみんなで予想する（tier.html）
- **絵描き人狼**：1人だけお題を知らない人狼を、みんなの一筆から見つけ出す（ekaki.html）
- **えしりとり**：絵だけでつなぐ伝言しりとり（eshiri.html）

部屋コードはどちらのゲームでも共通で、トップの「部屋コードで参加」に入れると自動で正しいゲームに移動します。
GitHub Pages（画面）＋ Firebase Realtime Database（通信）で動きます。サーバーを立てる必要はありません。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` / `hub.js` / `hub.css` | ゲーム選択画面 |
| `tier.html` / `tier.js` / `presets.js` | ティアよみ（presets.js はお題ガチャの一覧） |
| `ekaki.html` / `ekaki.js` / `ekaki.css` / `ekaki-presets.js` | 絵描き人狼（ekaki-presets.js はお題の一覧） |
| `eshiri.html` / `eshiri.js` / `eshiri.css` | えしりとり |
| `style.css` | 共通の見た目 |
| `common.js` | 共通の部品 |
| `version.js` | バージョン番号（ゲーム選択画面の下に表示。更新したら番号を上げる） |
| `loader.js` | 読み込み係。番号が変わると古いキャッシュを使わず新しいファイルを読み込む |
| `store.js` | 通信レイヤー（Firebase / ローカルテストモードを切り替え） |
| `firebase-config.js` | **Firebaseの設定を貼る場所** |
| `database.rules.json` | Firebaseのセキュリティルール |

## まずは手元で動作確認（Firebase不要）

`firebase-config.js` が空のままだと **ローカルテストモード** で動きます。
同じブラウザの複数タブ同士で通信するので、1人で全フェーズを確認できます。

```bash
cd tieryomi
python3 -m http.server 8000
```

1. タブ1で http://localhost:8000 を開いて「部屋を作る」
2. 「リンクをコピー」したURLを別タブで開いて参加（タブ3つ以上でもOK）
3. ゲームスタート

> ES Modules を使っているので、`index.html` をダブルクリックで開く（file://）のは不可です。

## 本番（友達とオンラインで遊ぶ）セットアップ

### 1. Firebase プロジェクトを作る
1. https://console.firebase.google.com で「プロジェクトを追加」
   （Googleアナリティクスはオフで大丈夫）
2. 左メニュー「構築」→「Realtime Database」→「データベースを作成」
   - ロケーション：シンガポール（`asia-southeast1`）が日本から近いです
   - 「ロックモード」で開始してOK（次の手順でルールを上書きします）
3. 「ルール」タブを開き、`database.rules.json` の中身を貼り付けて「公開」

### 2. Webアプリを登録して設定をコピー
1. プロジェクトの設定（⚙️）→「マイアプリ」→ `</>`（ウェブ）を追加
2. 表示される `firebaseConfig` の値を `firebase-config.js` に貼り付け
   - **`databaseURL` が必ず入っていること**を確認してください（無いとローカルモードになります）
   - 見当たらない場合は Realtime Database の画面上部に出ている URL をコピーして追加

> apiKey などは公開されても問題ない値です（Firebaseのクライアント設定は元々公開前提）。アクセス制御はルール側で行います。

### 3. GitHub Pages で公開
1. GitHub で新しいリポジトリを作り、このフォルダの中身を全部アップロード
2. Settings → Pages → Source を「Deploy from a branch」、ブランチ `main` / `/(root)` にして Save
3. 数分後 `https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べます

### 4. 遊び方
- 1人が「部屋を作る」→ 招待リンク（またはコードの4文字）を友達に送る
- 2人以上そろったらホストが「ゲームスタート」

## えしりとりの仕様

- **流れ**：全員が同時に自分の列を始める（スタートの文字はランダム）→ ステップごとに列が隣へ回る → 届いた絵が何に見えるか答え、その最後の文字から始まる言葉を描く → 最後の人は答えるだけ → 1列ずつ答え合わせ
- **人数・長さ**：3〜10人。1列の長さは「全員分」か「4枚まで」「6枚まで」。制限時間は 60/90/120秒/なし（時間切れはその時点の内容で自動提出）
- **言葉のルール**：ひらがな・カタカナで入力。「ん」で終わる言葉は描けない（答えが「ん」で終わったらひとつ前の文字から）。濁点・小さい文字のあり・なしは区別しない
- **得点**：絵が伝わる（答えが描いた言葉と一致）たびに、描いた人 +1・答えた人 +1。ほぼ同じ答え（例：いぬ／こいぬ）は答え合わせ中に誰でも「⭕」にできる
- **その他**：絵に❤️（いいね）／称号（画伯賞・伝える力・解読王）／いいねが多かった絵のギャラリー／何ラウンドでも続けられ、合計点で順位

## 絵描き人狼の仕様

- **お題の決め方**：「おまかせ」（全員参加・12ジャンル144個からランダム、3人〜）／「出題者が決める」（交代で1人が出題者になり描かずに見守る、4人〜）
- **流れ**：役職カードをめくって確認 → 順番に一筆ずつ描く（1〜3周）→ 投票 → 人狼が単独最多票なら人狼がお題を回答 → 結果
- **一筆**：指（マウス）を離すまでが一筆。離したあと「描き直す」か「決定」を選べる。描いている途中の線も他の人にリアルタイムで見える
- **人狼の回答**：ひらがな・カタカナ・別表記（例：りんご／林檎）は自動で正解判定。一致しない場合は人狼以外の誰かが「正解／不正解」を判定
- **得点**：人狼の勝ち → 人狼 +3 ／ 市民の勝ち → 市民 +1 ／ 勝敗に関係なく人狼に投票した市民 +1
- **その他**：人狼は1番手にならない／投票画面で名前をタップするとその人の線だけ表示／結果画面で描いた順に再生／最終結果に全ゲームの絵のギャラリー
- お題の追加は `ekaki-presets.js` に。`'りんご|林檎|リンゴ'` のように「|」区切りで別表記を書くと自動判定の対象になります

## ティアよみの仕様

- **進行**：お題決め → ティア作成（出題者と予想者が同時に）→ 全員提出で自動的に正解発表 → 次の出題者へ
- **得点**：段がぴったり +3 ／ 1段ズレ +1 ／ 5つ全部ぴったりでボーナス +5（1問最大20pt）。出題者はその回0pt
- **周回**：ロビーで 1〜3周 / エンドレス を選択。全員が規定回数出題したら最終結果へ
- **ホスト**：参加順で最初のオンラインの人。抜けると自動で次の人に移ります
- **切断対策**：リロードしても同じタブなら自動復帰・作りかけのティア表も保持。
  切断した人がいる場合、ホストは「待たずに発表」「出題を次の人へ回す」ができます
- **途中参加**：お題が出た後に入った人はその回だけ観戦、次のお題から参加
- **最終結果**：表彰台・称号（一番の理解者／ニアピン王／エスパー／読まれやすい人／ミステリアス）・全問のふりかえり

## 注意点

- 身内向けの作りなので、開発者ツールを使えば提出前に他人の回答を覗くことは技術的に可能です
- 部屋データは自動では消えません。気になったら Firebase コンソールの「データ」タブで `rooms` を削除してください（無料枠の容量にはまず届きません）
